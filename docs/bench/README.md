## 三、提示词包（bench/prompts）

这些文件是给 `测试提示词包` 导入用的纯文本，不是代码。

| 文件 | 规模 | 覆盖 |
|---|---|---|
| `测试提示词-多维度-2026-10-29.txt` | 10 组 46 条 | A 组合 6 / B 文字 8 / C 海报 5 / D 写实 4 / E 插画 4 / F 图像理解 4 / G 编辑 5 / H 推理 3 / I 中文语境 3 / J 鲁棒性 4 |
| `功能测试文本集-2026-10.txt` | 22 条 | 冒烟：16 功能各 1 条 + 4 条难点 + 2 条边界 |
| `功能测试文本集-完整版-2026-10.txt` | 68 条 | 加深：每功能 L1–L4 各 1 条 |

> 多维度集导入后实际建 **42 条文生图用例**：F 组 4 条是看图题（`输入图：` / `提问：`），
> 缺真实底图，导入时会明确跳过。文字组（B）出现错字直接判 0，别用「看着还行」放过。

### 导入方式

Web 测试台侧栏「导入提示词包…」→ 选文件 → 填尺寸 → 一次建用例。

- 识别两种格式：`[A1 标题]` + `输入：…` 块，或一行一条；
- 自动跳过 `#` 注释、`===` 分隔线、`判定：` 行；
- 按提示词哈希去重，重复导入不长副本；
- `输入图：` / `提问：` 的看图题不建文生图用例（缺真实底图），会明确告知跳过；
- 单次上限 80 条。

### 评分口径

多维度提示词文件里每条都带可勾选的判定项。硬线：

- **文字组出现错字直接 0 分**（商用等于废图）；
- **编辑组非编辑区被改动直接 0 分**；
- 硬约束不过最多 3 分。

## 四、用例与数据

```
bench/cases/<caseId>.json        用例定义（提示词/参数/预期/类别）
bench/assets/                    固定素材（scene / poster / mask / lineart / style …）
bench/out/<runId>/               每次 CLI 运行的自包含快照（images + report + prompts.md）
bench/preview/                   预览页临时输出（可随时清空）
```

单条用例在插件侧的数据：

```
<PluginData>/dev/bench/cases/<caseId>/
├── case.json                    输入哈希、提示词、参数、基准 runId
├── input.png                    冻结画面
├── mask.png                     白=选区（按功能导出）
├── assets/asset_N.png           选中图层、画布对齐
└── runs/<runId>/
    ├── output.png
    └── meta.json                延迟/尺寸/评分/备注/provenance/error
```

**跨机复现**：侧栏「导出用例包」→ 另一台「导入用例包」，输入图、蒙版、资产、提示词、参数一起带走。
复现成立的前提是**工作流与模型文件一致**；对不上时先看 `workflowHash` 与模型文件名，不要先比画质。

## 五、当前覆盖边界

- **本地 ComfyUI 只接了一条文生图工作流**：相似图、重绘、拼合等需要参考图的用例会被拒绝（400 并说明原因），
  不会静默生成一张与输入无关的图。
- 编辑域需要一条带 `LoadImage`（标题 `INPUT`）与 `LoadImageMask`（标题 `MASK`）的 inpaint 工作流。
- 拆图自动分割（SAM2 / BiRefNet）未接入；当前靠生成模型 + 纯色底抠色。
- 人像精修、扩图不纳入 bench：前者需要真实人像素材，后者依赖 PS 改画布，脱离 PS 测的是另一件事。
