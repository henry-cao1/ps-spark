# PS Spark 产品路线图（2026-11 → 2027-05）

> 基线版本 **1.7.1**。目标：从「单图精修工具」变成「可批量、可拆解、可协作的 PS AI 工作台」。
> 原则：本地优先、BYOK、结果可编辑、不转售 API、不做模型超市。

## 0. 判断依据

竞品已经覆盖「开箱即用」：StartAI / 图钉AI 有 50+ 功能和模板库，Layer.ai 有多模型与团队会话，
OpenLayer 也做 ComfyUI + 拆层。继续拼功能数量没有胜算。

我们可守的三块阵地：

1. **落图精度**：选区/图层输入、原坐标回贴、比例不符时 cover-fit + 蒙版裁边、按任务快照隔污。
2. **拆图可编辑性**：纯色底探测、原图像素重建、alpha 重建蒙版，而不是输出几张 PNG。
3. **云端 + 本地同队列**：2 路云端、1 路本地、按序落图、可取消可追加，数据与成本可控。

路线图按「先补短板，再筑墙，最后平台化」推进。

## 2. P0 · 0–3 个月：让新用户跑起来，让团队能批量干活

### P0-1 启动自检向导

**问题**：新用户装完后最常见的失败是「不知道缺什么」——PS 版本低、Key 没填、ComfyUI 没启动、
模型文件不在。现在只能靠日志和文档排查。

**范围**
- 触发：首次启动、升级后首次启动、设置页手动「环境自检」。
- 检查项：
  1. Photoshop 版本 ≥ 24.4，UXP 面板可加载；
  2. 服务地址可达（超时/证书/代理区分）；
  3. API Key 有效（用最小请求验证，不产生生成费用）；
  4. 文本/看图模型可用（拆图、提示词助手依赖）；
  5. ComfyUI `/system_stats`、`/object_info` 连通性；
  6. 每个本地预设的模型文件、节点类、必填参数是否齐全；
  7. 历史目录可写、磁盘余量。
- 输出：一张清单，每项「通过 / 缺失 / 可忽略」，附一条可执行修复动作；
  支持「复制诊断包」（版本、配置摘要、最近日志，脱敏后导出）。
- 不做：自动下载模型、自动改用户环境。

**验收**
- 干净机器从安装到首张成功图 ≤ 5 分钟，不需要看文档；
- 断网、错 Key、ComfyUI 未启动、缺模型四类故障都能定位到具体项；
- 诊断包不含 Key、路径中的用户名可脱敏。

**复杂度**：中。复用现有 `diag`、`comfyProbe`、`comfyClassInfo`。

### P0-2 批量处理

**问题**：StartAI 的核心优势是批量。我们目前一次只能跑一张，电商多 SKU、多色、多规格场景
完全接不住，而这是企业最愿意付费的能力。

**范围**
- 输入源：文件夹、当前打开的多文档、CSV/JSON 清单。
- CSV 字段：`file`、`prompt`、`model`、`size`、`tool`、`output`、`tags`；
  支持 `{{color}}`、`{{scene}}`、`{{sku}}` 占位符做笛卡尔积（商品 × 颜色 × 场景）。
- 执行：复用现有队列；云端 2 路、本地串行；逐条落图/导出，支持 PNG/PSD；
  单条失败不中断整批，失败项可重试；崩溃后从断点续跑。
- 预览与成本：入队前展示前 3 条、总条数、按模型估算费用/耗时；支持 dry-run。
- 命名：模板化输出名（`{sku}_{color}_{index}`），自动去重与非法字符处理。
- 结果：批次报告（成功/失败/跳过、耗时、费用），失败项附日志片段。

**验收**
- 100 张图无人值守跑完，失败率 < 2%，失败可单独重试；
- 同一批内不同模型/工具可混排；
- 中断后重启能续跑，不重复扣费；
- 输出命名稳定，CSV 可回读核对。

**复杂度**：高。依赖队列、落图、历史三条链路，建议先做文件夹 + CSV，再做多文档。

## 3. P1 · 3–9 个月：把拆图和一致性做成护城河

### P1-1 拆图 2.0

**现状**：依赖模型遵守「纯洋红底 + 位置不变」，遮挡区域无内容，文字仍是像素。

**范围**
- **文本指代分割**：接 SAM2 / GroundingDINO（本地 ComfyUI 节点或独立服务），
  用自然语言指定要拆的元素，不再只靠色键；色键保留为无分割模型时的兜底。
- **遮挡补全**：元素层被其它元素挡住的部分，用 inpaint 补全，移动/缩放后不露底。
- **阴影/反光独立层**：把投影、倒影、环境光拆成可选层，合成时可单独调。
- **OCR → 可编辑文字层**：识别文字内容、位置、字号、颜色，生成 PS 文字层；
  字体不可用时给出最接近的替代并标注。
- **调整层输出**：按区域生成曲线/色相饱和度/色阶调整层，保留可调性。
- **批量拆图**：文件夹/多文档，输出 PSD 或图层组，支持统一命名。

**验收**
- 10 类常见图（海报、商品、人物、UI、插画、截图、logo、文字图、透明物体、复杂遮挡）
  元素层可编辑率 ≥ 90%；
- 遮挡补全后移动元素不出现透明洞；
- 文字层可改字号/颜色，位置误差 ≤ 2px；
- 单图拆图人工修正时间 ≤ 2 分钟。

**复杂度**：高。建议先做分割 + 遮挡补全，再做文字层与调整层。

### P1-2 工作流生态

**问题**：本地模型适配已经是差异化，但预设无法分享，换机器/换团队要重配。

**范围**
- **预设包**：`.psspark-preset.zip`，含 `workflow.json`、`models.json`（模型文件名、节点类、
  必填参数、可选哈希）、`README.md`、缩略图；支持导出/导入/版本号。
- **缺节点提示**：探测到缺节点时，给出 ComfyUI Manager 的安装项名称与链接，
  不再只报「缺节点」。
- **补齐模板**：Flux Kontext（指令编辑）、Qwen-Image（文生图/编辑）、SDXL inpaint、
  ControlNet（canny/depth）、LoRA 叠加、放大（ESRGAN/4x-UltraSharp）。
- **能力声明**：预设明确声明 t2i / i2i / inpaint / mask / alpha，提交前做能力闸门。

**验收**
- 在干净机器导入预设包，能准确列出缺的模型/节点，并按提示装完后一次跑通；
- 预设包跨机器导入后无需手改路径；
- 至少 6 条官方模板覆盖主流架构。

**复杂度**：中高。依赖 services.js 的适配层与 ComfyUI 探测缓存。

### P1-3 一致性

**问题**：跨任务保持同一角色/商品/风格，目前只能靠重复写提示词。

**范围**
- **主体库**：角色、商品、logo、风格四类；每条含参考图、提示词片段、可选 LoRA/embedding、
  默认模型与参数。
- **锁定**：任务可勾选「锁定主体」，自动带入参考图与提示词片段；生成/编辑/拆图共用。
- **种子与参考图库**：记录种子、模型版本、参考图，支持复现与微调。
- **跨任务**：同一主体在文生图、局部重绘、原位合成、拆图之间保持 ID 与描述一致。

**验收**
- 同一商品生成 10 张不同场景图，主体外观/颜色/logo 一致率 ≥ 90%；
- 同一 seed + 参数可复现；
- 主体库可导出/导入，随预设包迁移。

**复杂度**：中。先做提示词片段 + 参考图，再接 LoRA/IP-Adapter。

### P1-4 画布体验

**范围**
- 面板内画笔蒙版：涂抹/擦除、羽化、反选、扩展/收缩，替代来回切 PS 快速蒙版。
- 前后对比：参考图/结果、候选之间、跨模型，支持并排与滑动。
- 非破坏性智能对象管线：结果以智能对象落图，保留源图与参数，可回改重跑。
- 局部重做：在结果上圈一块只重画该区域，其余像素不动。

**验收**
- 蒙版编辑可撤销，落图边缘无明显接缝；
- 智能对象可无损缩放，重新打开文档仍可改参数；
- 局部重做不改变选区外像素（逐像素校验）。

## 4. P2 · 9–18 个月：平台化，但不发散

### P2-1 无头 CLI / 批处理 API

- 复用 `registry` 与执行器，提供 `psspark run --tool ... --input ... --out ...`；
- JSON 输出、退出码、dry-run、并发/重试参数；
- 通过 PS Actions / 批处理脚本接入企业流水线；
- 不做独立渲染引擎，仍以 Photoshop 为执行宿主。

**验收**：CI 中可跑通一条「输入文件夹 → 批量抠图 → 输出 PNG」的流水线；错误码可区分配置/网络/PS 故障。

### P2-2 本地优先协作

- 共享预设/历史：用户自己的存储（S3/WebDAV/iCloud/局域网），插件只做同步与索引；
- 审阅链接：导出带标注的对比页，客户可评论，不回传原图；
- 团队策略：统一模型白名单、默认参数、禁用项；
- 明确不做强制云、不做账号体系。

**验收**：两人共享一套预设与历史，冲突可合并；审阅链接可撤销、可设过期。

### P2-3 插件 SDK

- 开放 registry 扩展点：工具声明、提示词模板、参数 schema、执行器适配；
- 提供示例插件与类型定义；第三方工具可独立分发；
- 安全边界：权限声明、网络域名白名单、禁用任意代码执行；
- 许可证：SDK 采用与主项目兼容的 AGPL 例外条款，避免闭源插件直接被吞。

**验收**：外部开发者按文档在 1 天内接入一个自定义工具；主仓库测试不受影响。

### P2-4 宿主扩展

- 仅在明确需求后评估 Illustrator（矢量生成/分层）与 Figma（设计稿生成）；
- 优先复用 registry 与提示词层，不复制一套执行器；
- 没有付费客户或社区需求前不启动。

## 5. 里程碑与指标

| 阶段 | 指标 | 目标 |
|---|---|---|
| 1.8 | 新用户首图成功率 | ≥ 80%，无需人工支持 |
| 1.8 | 批量 100 张无人值守 | 失败率 < 2%，可续跑 |
| 1.9 | 拆图元素可编辑率 | ≥ 90% |
| 1.9 | 预设包跨机导入成功率 | ≥ 95% |
| 1.10 | 同主体 10 图一致率 | ≥ 90% |
| 2.0 | CLI 流水线 | 一条端到端示例进 CI |
| 2.1 | 外部 SDK 工具 | ≥ 3 个社区工具 |

隐私约束：不引入默认埋点；指标通过本地报告、用户主动提交的诊断包和公开 Issue 统计。

## 6. 依赖与风险

- **顺序**：P0-1 先于 P0-2（批量失败时要有可读的自检信息）；P1-1 的批量拆图依赖 P0-2；
  P1-2 的预设包是 P2-3 SDK 的前置。
- **SAM2/GroundingDINO**：本地部署重、显存要求高；做成可选依赖，保留色键兜底。
- **OCR 字体匹配**：只能给出近似字体，验收以「可编辑、位置准」为主，不承诺像素级一致。
- **批量成本**：入队前必须给估算与确认，避免企业用户误跑大单。
- **SDK 安全**：第三方代码权限过大，需白名单与审核流程；AGPL 例外条款要请法务确认。
- **人力**：以上按 1 名全职开发 + 1 名兼职测试估算；P1 拆图 2.0 建议单独排 6–8 周。

## 7. 非目标

- 不做模型超市、不转售 API、不做强制账号/云存储；
- 不做移动端/网页版编辑器；
- 不承诺视频生成；
- 不为「功能数量」堆工具，新增工具必须进入 registry 并有验收用例。
