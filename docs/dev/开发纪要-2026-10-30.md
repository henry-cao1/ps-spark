## 3. 关键设计决策（以及为什么）

### 3.1 技术底座

- **UXP 原生，不做 CEP**：manifest v5、零运行时依赖、纯 UXP API。代价是 UI 能力弱（无 `confirm`、flex 不可靠），收益是安装体积与跨平台。
- **注册表驱动**：`registry.js` 一条声明 = 一个功能（槽位、提示词、参数、选区要求）。新增功能不改渲染代码。
- **渲染三闸门**：组件出现 = 声明 ∩ 服务能力 ∩ 上下文。避免「声明了但没有模型支持」的空控件。
- **提示词声明式化**：`promptSpec`（branches + `{{user}}` 占位）替换闭包模板，才可能让非程序员在开发者模式里编辑；旧模板保留回退，`test-prompts` 做 128 条逐字符对照。

### 3.2 本地模型

- **ComfyUI 走 HTTP，不做进程管理**：插件只提交 `/prompt`、轮询 `/history`、取 `/view`；启停交给 `Start-ComfyUI.*`。
- **预设 = 一条工作流**：`{url, workflow, roles, overrides, caps, alpha}`。角色用节点标题约定（PROMPT / NEGATIVE / INPUT / MASK / SIZE / OUTPUT），找不到退化为类型启发式。
- **能力闸门**：预设声明 `t2i / i2i / inpaint / segment`，不匹配的选项灰掉并说明原因；服务端也拒绝，避免「静默生成一张与输入无关的图还记成有效结果」。
- **可复现**：用例可固定 seed，运行写 `provenance`（seed / workflowHash / 采样参数 / 模型文件 / 预设）；结果卡显示 `seed · wf 指纹 · 步数/CFG`。
- **多机**：一个预设 = 一条工作流 + 多个地址，运行时探测并选第一台在线的；不同模型仍需各自工作流（模型文件名与架构节点不同）。

### 3.3 队列与并发（1.7 Beta 2）

- **槽位限流**：`cloud: 2`、`local: 1`、`edit: 1`。云端 2 路是「同一 Key 限流风险」与「等待收益」的折中；本地单实例只能串行；编辑要动画布与选区，必须独占。
- **生成与落图分离**：并发生成允许乱序完成，但写图层按入队 `seq` 排队（`waitPlaceTurn`）。这样图层叠放顺序等于点击顺序，不因某张快就插到前面。
- **运行上下文隔离**：图层名、参考图、`lastRun` 以前是全局变量，两条并发会互相覆盖。现在每次运行有独立 `run` 对象，结束时才同步给界面。
- **取消语义**：只有一条在跑时才真 `abort`（全局 abort 会误伤另一条）；多路并发时取消 = 标记 + 阻止落图，在途请求自然结束。
- **编辑任务记住选区**：入队时把选区复制成临时通道 `pssparkQ<taskId>`，执行前还原，跑完删除；换文档则跳过。

### 3.4 品牌与开源

- **显示名 `PS Spark`，manifest id 保留 `com.psspark.ps.assistant`**。原因不是懒：UXP 的 localStorage 按 origin(id) 隔离、secureStorage 走 macOS 钥匙串且按 id 绑定，改 id 等于 Key/预设/历史全丢。已在 10-29 实际踩过一次并回退。
- **接口域名一个没动**（`grsai.dakka.com.cn`、`image.grsai.ai`）；存储键当时保留 `grsai.*`，
  开源前已统一改为 `psspark.*`（见 §27）。
- **AGPL-3.0**：早期排期建议 Apache-2.0，最终选 AGPL，理由是「不让别人拿去做闭源商业产品」。同时明确它的边界：**拦不住原样打包转卖**，真正起作用的是免费发布 + 常驻提示 + 商标条款。
- **防倒卖提示**：顶栏下方常驻一行，不可关闭；仓库地址填进 `js/brand.js` 后自动变成可点击链接。

## 4. 踩过的坑（按主题，都是实际发生过的）

### 4.1 UXP 布局

| 现象 | 根因 | 结论 |
|---|---|---|
| 面板重叠、鬼影 | UXP 对绝对定位覆盖层重绘不可靠，`visibility:hidden` 仍穿透 | 底层必须 `display:none !important`；同一时刻只绘制一个面板 |
| 输入框被压成一条线 | 纵向 flex 分配高度，`flex:none` 不可靠 | 滚动内容区一律块级流 + 显式高度；四边拉伸代替 `100%` |
| 按钮粘在一起 / 间距忽大忽小 | `gap` 在 UXP 不稳 | 相邻 `margin-left` 兜底 |
| 齿轮比 Tab 窄且高 | `<button>` 不认 `flex-basis`、自带内边距 | 齿轮改 `div.tab` |
| 下拉值居中留左白 | UXP 忽略 button 的 `text-align` | `justify-content:flex-start` + 值 `display:block` |
| 滚动卡顿 | 每个 wheel 事件同步写 `scrollTop` | 按 `deltaMode` 换算像素 + rAF 合并 |
| `window.confirm` 没反应 | UXP 未实现，调用直接返回 false | 删除改两段式确认（按钮变红，4 秒内再点） |
| 面板变窄文字被裁 | 父容器 `nowrap` 继承 | 说明文字内联 `white-space:normal` + `word-break` |

### 4.2 PS / 侧载 / 存储

- **PS 只在启动时加载插件**：装完必须完全退出再开。
- **OpenUXP 1.0.5 会把 `manifest.host` 从对象改成数组**，PS 直接拒载；日志在 `~/Library/Logs/Adobe/Adobe Photoshop 20XX/UXPLogs_*.log`，错误写得很明确。
- **`PluginsInfo/v1/PS.json` 不会自动重扫 External**：目录名必须是 `<id>_<version>`，换版本号要同步改目录名或改注册表。
- **改 id = 配置全丢**：复制 `PluginsStorage/<id>` 目录无效，origin 变了；钥匙串项也不认新 id。这是 10-29 最重要的一条教训。
- **`rsync --delete` 被系统安全策略拦**：改用 `cp -R`；`mv` 也可能被拦。
- **Adobe 应用拒绝 AppleScript 退出**（`-10004 privilege violation`）：重启 PS 只能手动 `Cmd+Q`。

### 4.3 接口与数据

- **PS 导出的 data URI 实际是 JPEG**：尺寸解析必须同时支持 PNG/JPEG/WebP。
- **环境代理会骗人**：`HTTP_PROXY` 对未监听端口返回 502，`curl` 退出码仍是 0。判断服务在线要 `--noproxy '*'` 且比对 `%{http_code} == 200`。
- **comfy 单张路径漏判**：多候选路径有判断、单张路径没有，把 `comfy` 当云端模型 id 发出去，服务端回 `model not register: comfy`。修在 `runGenerationsPlain` + `callApi` 兜底。
- **ComfyUI 工作流 JSON**：几 KB 粘贴进 UXP 文本框会截断，改成选文件导入；UI 格式（含 `nodes`/`links`）要拒绝。

### 4.4 队列

- **取消「无效」**：ComfyUI 每 1.5 秒轮询，点取消时常处在两次轮询之间，没有在途请求可 abort；运行条取消又没告知队列，任务挂到 5 分钟超时。修法是运行级标志 + 任务级探针。
- **只插最后一张**：多候选要手选，队列跑下一条时 `lastRun` 被覆盖，前一条没入口。队列任务改为自动插第 1 张，其余进历史。
- **运行中按钮被禁用**：`setRunning(true)` 与 `refreshRunBar` 两处都在禁用，是队列之前的旧逻辑。
- **并发互相污染**：全局 `lastLayerName` / `lastExportUri` / `lastRun`，已改为 `run` 上下文。

### 4.5 工程

- **rAF 在 headless 不回调**（UXP 无重绘时也可能），测量逻辑改同步执行。
- **测试脚本曾经只放在 `/tmp`**，被系统清理丢过一次——这是后来「测试必须入仓」的直接原因。
- **构建必须分渠道**：release 排除 `js/dev`、剥离 DEV 块、扫描禁用字符串；dev 产物才带开发者工作台。

## 5. 当前架构

```
ps-spark-plugin/
├── manifest.json          UXP 清单（id 沿用 com.psspark.ps.assistant）
├── index.html             结构 + 全部样式（UXP 单页）
└── js/
    ├── registry.js        16 个功能声明 + 提示词模板（promptSpec）
    ├── services.js        配置/模型/本地预设/密钥
    ├── api.js             云端请求 + ComfyUI 提交轮询 + 取消
    ├── ps.js              Photoshop 操作（选区/蒙版/落图/智能对象/抠色）
    ├── store.js           任务归档（历史）
    ├── ui.js              公共组件（下拉/行/运行条/结果卡）
    ├── diag.js            日志、进度、诊断
    ├── brand.js           品牌、仓库地址占位、许可证
    ├── dev/devmode.js     开发者工作台（仅 dev 构建）
    └── app.js             三域渲染 + 运行管线 + 队列调度
```

运行管线（简化）：

```
点击 → captureSnapshot → TASKQ 入队（cloud/local/edit 槽位）
     → startTask：还原选区 → runCurrentInstance
         → 导出参考图/蒙版 → callApi / callComfyUI → 下载结果
         → waitPlaceTurn（按 seq 等前面落图）→ executeAsModal 写图层
     → 归档历史 → 下一条
```

## 9. 一页结论

9 月 22 日是一个 `main.js` 原型，10 月 30 日是 1.1 万行、16 功能、544 项断言的插件，
中间真正花时间的不是「加功能」，而是三件事：**把 UXP 的坑一个个踩平、把运行管线从单体拆成可并发的两段、
把测试从 `/tmp` 搬进仓库**。功能清单会继续变，这三件事是后面所有改动的地基。

## 10. 多语言与开源构建（2026-10-30 晚）

- 新增 `js/i18n.js`：词典以中文原文为 key（`I18N.dict.en`），`t()` 供拼接文案使用；

## 13. 队列输入固定：不能用上一条任务的结果当原图（2026-11-01 深夜）

### 现象
老照片修复 / 线稿上色：先用本地模型跑一条，再切云端模型跑同一条。云端任务拿到的是
**本地刚写入的结果层**（在它的基础上再改一次），而不是用户点击时的原图。
日志表现：第二条任务的「导出区域图像」里已经包含第一条的结果（来源是 `app.activeDocument` 的合并可见）。

### 根因
队列只保存了**参数与选区**（`snap` + 选区通道），没有保存**画面本身**。
图片是在任务真正执行时才导出的，此时前一条任务的结果层已经在文档里 → 合并可见就把它算进去了。
另外编辑任务统一占 `edit` 槽（上限 1），云端也只能排队等本地跑完，进一步放大了这个问题。

### 修法
- **入队快照图层**：`enqueueCurrentRun` 记录 `t.layerIds = collectLayerIds(doc)`（递归含组内图层）。
- **导出前临时隐藏新增图层**：`withSourceSnapshot(ctx, fn)` 在 `executeAsModal` 内
  `hideLayersNotIn(doc, t.layerIds)` → 导出 → 立刻 `restoreLayerVisibility()`。
  隐藏窗口只有几十毫秒，用户看不到；导出结果就是点击那一刻的画面。
  覆盖：`runEditPipeline`（编辑域）、`exportMainForRefs`（参考图/合成）、`execOutpaint`（扩图参考图）。
- **选区也按入队固定**：`t.selBounds` 存下入队时的选区，执行时不再读当前选区；
  若入队时有选区但通道没存下来，直接报错跳过（宁可不跑，也不改错整张画布）。
- **槽位细分**：`taskSlotOf(inst, local, hasSel)` —— 带选区的编辑任务仍占 `edit`（选区是全局状态，必须独占）；
  不带选区、只处理整幅画面的编辑任务（老照片修复、线稿上色等）改用 `cloud` / `local` 槽，
  于是本地 1 路 + 云端 2 路可以真正并发，不必等前一条结束。
- 并发时活动文档可能被别的任务切走：导出前 `ensureActiveDoc(ctx.docId)`，队列任务优先按 `t.docId` 取文档。
- `enqueueCurrentRun` 改为 async（要读选区），UI 调用处补 `.catch` 避免未处理异常。

## 14. 扩图对齐修复：尺寸档位 · 蒙版 · 铺满回贴（2026-11-01 夜）

### 现象
扩图结果「扩展区域远大于设定值、与原图不对齐、整张被缩放」。

### 根因（三条叠加）
1. 请求 `size: "auto"`：接口按自己的档位出图（常见 1:1）。导出参考图是 `NW×NH`，
   输出比例不同 → `placeEntryAsLayer` 走**等比 contain**，结果被缩小后居中写进扩展画布，
   左侧/上方留边 → 原图位置整体偏移，扩展边看起来"变大"。
2. 参考图直接按扩展后画布导出。2471×2470 用 100% 扩展 → 7413×7410 的 PNG（10.9 MB），
   网关必然自行降采样，原图在参考图里只剩几百像素，模型于是重新构图/放大主体。
3. 没有任何蒙版约束：模型会把整张画面重新生成，原图区域也会被改写。

### 修法
- `outpaintRefGeometry()`（纯函数，可单测）：扩展后画布按最长边 2048 等比缩成参考图，
  原图矩形的位置/尺寸按同一系数换算，`原图区 + 左右边 = 参考图宽`（不留 1px 缝）。
- 请求尺寸改用 `decompPickSize(RW,RH,模型,true)`：只从模型**支持表**里挑与目标同比例的档位
  （4:3 画布 → `1443x1090`，1:1 → `1024x1024`），找不到才回 `auto`。
- 新增 `buildOutpaintMaskPNG()`：白＝扩展边（可重绘），黑＝原图矩形（保持），随 `edits` 一起发送。
  nano 族无蒙版能力，靠提示词 + 落图后挖回原图区。
- 回贴改 `{ stretch: true, punchRect: {原图矩形} }`：
  - stretch：结果铺满 `(0,0,NW,NH)`，比例不一致也不留边、不错位（比例差 >5% 时给出提示）；
  - punchRect：结果层加蒙版把原图矩形挖空，**原图区域一定是用户自己的像素**，
    模型怎么重构图都影响不到它，位置按原坐标锁死。
- 提示词加「硬性要求」三条（画幅一致 / 原区域不得缩放移动 / 只补全透明区），
  `promptTpl.text` 与 `promptSpec` 保持逐字符一致（test-prompts 会对照）。
- 参数区新增尺寸预览：「扩展后画布 1620×1216（原 1080×810 · 左 270 / 右 270 / 上 203 / 下 203 px）」，
  避免把「100%」误解为放大一倍（实际是 3 倍画布）。

### 测试
- `test-comfy.cjs` 89 项：新增几何换算（小画布 k=1 / 7413×7410 → 2048×2047 比例不变 /
  原图区+边=画布）、尺寸档位（1:1→1024²、4:3→1443×1090），以及扩图全链路仿真
  （临时画布 1620×1216、请求 `1443x1090`、带蒙版、`canvasResizeTo(…,270,203)`、
  `stretch + punchRect`）。
- 全量 615 项通过；dev / release / oss 重建，release 隔离 20 文件。

## 16. 拆图「建立/羽化 命令当前不可用」根治（2026-11-01 晚）

### 16.1 先看日志，不猜
`PluginData/psspark_debug.log` 里那次拆图的真实序列：

```
15:24:53.633 clip: layer mask from selection created   ← 抠色建蒙版成功
15:24:53.651 colorKey: 抠底色完成（容差 26）
15:24:54.990 selection: feather 1px                    ← 羽化命令本身没报错
15:24:55.003 rebuild: 生成层没有可见像素（选区为空）   ← 切图层后选区就空了
```

结论：**「羽化/建立不可用」不是命令偶尔抽风，而是选区在这条链路上本来就不成立**——
「载入图层蒙版为选区」拿到的常常是空选区（蒙版全黑），空选区下 `make` 必然被 PS 拒绝，
报出来的就是「命令"建立"当前不可用」；用户完全无从判断。

外部核对（Adobe 开发者论坛 2026-09 帖）：PS 27.9.1 起，Apple Silicon 上在**同一个 modal
作用域内连续 batchPlay** 时，创建图层蒙版会稳定报 `Make is not currently available`，
社区确认的绕过方式是「把命令放到 `setTimeout` 回调里、让出主线程后再执行」。
两条线索合起来说明：这条「选区 → 羽化 → 建蒙版」路线本身就该换掉。

### 16.2 修法一：命令层——「拒绝执行即重试」
`isCmdUnavailable(e)` 判定「当前不可用」类错误。关键语义：**PS 抛这个错时命令根本没执行**
（执行前就被拒），所以重试绝对安全，不会产生「建两次蒙版」这类副作用。

`batchPlay()` 现在内置 `[0, 140, 320]ms` 三拍重试（`await setTimeout` 真正让出主线程，
等价于社区那个 `setTimeout` 绕过）；`batchPlayRetry()` 保留作显式多等一拍。
影响面是全局所有命令，不再只盯着 `make`。

### 16.3 修法二：链路层——元素层重建改「剪贴蒙版 + 合并」
`rebuildLayerWithOriginalPixels()` 主路径重写（v2）：

1. 置入原图（落在生成层正上方）；
2. `groupEvent` 把原图**剪贴**到生成层——下方层的 alpha / 图层蒙版直接当形状；
3. 选中两层 `mergeLayers` 合并成一张干净的像素层。

全程**不载入选区、不羽化、不建蒙版**，报错的两个源头直接消失。
`groupEvent` 的描述符按 Adobe 论坛 + ExtendScript 录制写法：只给 `_target` 与 `_isCommand`，
不带 `group`/`clipping` 参数（多给字段反而不生效）。

防呆：命令不报错 ≠ 生效。剪贴后 `get` 当前层校验 `group === true`（或 `clipping === true`），
拿不到就判定失败、清掉刚置入的原图，退回 v1；**绝不让原图整幅盖住元素层**。
`mergeLayersByIds()` 合并失败同样清理后回退。

v1（选区蒙版路径）保留为兼容回退，但每步都自证：
- `selectionNonEmpty()`：先确认选区真有面积（宽高 > 0.5px），空选区直接跳过；
- `applySelectionAsLayerMask()`：无选区 / 当前是背景图层（背景层不能加蒙版，是「建立不可用」
  的另一大来源）都直接返回 false，不再惊动 PS；像素删除兜底也包了 try；
- `featherSelection()` / `contractSelection()`：调用前先查选区，空选区跳过并记日志。

### 16.4 修法三：抠色结果自检
`cutLayerByColorKey()`：
- 魔棒点完先校验选区（点到透明区/纯色整幅时选不出东西，反选=全选，建蒙版等于没抠）；
- 建完蒙版后把蒙版载回选区自检：**全黑蒙版 = 一个元素像素都没抠到，图层会整体不可见**，
  这时删掉蒙版、保留模型原样，并在层状态里显示「抠色失败（保留模型输出）」——
  比留一个"看不见的层"可操作得多。

### 16.5 其他
- 拆图写入的 `execModal` 开头显式 `ensureActiveDoc(outId)`：命令作用在「前台文档」，

## 18. 拆图：nano 模型不守纯色底 + 合并后丢蒙版（2026-11-02 凌晨）

### 18.1 日志证据
```
16:02:28 decomp req 1/2 [白幽灵] · 纯色底 · size=1:1
16:03:10 colorKey: 魔棒未选中任何区域（点 (1,1)）
16:03:10 rebuild: 生成层覆盖整幅且无有效蒙版（1024×1024），判定为不透明输出 → 保留生成层
```
拆图模型是 nano-banana-2.1。魔棒在 (1,1) 点不出什么，说明**角落不是纯洋红**——
模型没按「纯洋红底」输出，而是画了一张完整场景图（或背景是渐变/纹理）。
于是整层被判为"不透明输出"，元素层 = 整幅生成图：既没有蒙版，形状也跟蓝图对不上。
两条日志合起来就是用户看到的现象：「蒙版也没有，指令也是错的」。

### 18.2 修法一：先探测纯色底，再决定抠不抠
`decompProbeKeyBg(docId, layerId)`：用 `imaging.getPixels` 把生成层降到 64×64，
取四角各 8×8 的平均色，算最大通道偏差 `spread`。
- `spread ≤ 24` → 四角同色，可信的抠像底，交给魔棒；
- 否则 → 直接判定「模型没照做」，**不浪费一次魔棒**，层状态显示「模型未给纯色底」；
- 读像素失败 → 返回 null，按原逻辑继续试（不影响老环境）。

拆图流程跑完后，若有层命中这种情况，日志区给一条明确提示：
「⚠ N 层没拿到纯洋红底…建议把拆图模型换成 gpt-image-2 / 2.5 后重试」。
拆图面板的模型行也会在选中 nano 系列时显示同样的提醒（`isNanoModel` 判断）。

### 18.3 修法二：提示词按「绿幕」写
`buildDecompLayerPrompt` 的纯色底段重写：
明确 RGB(255,0,255)、类比「影视绿幕那样的抠像底色」、强调「背景是平的色块，不是画面内容」，
并逐项排除渐变/光照/阴影/纹理/噪点/场景/地面/桌面/天空。nano 这类偏创作的模型对
"纯洋红"这种抽象词不敏感，但对"绿幕/色卡"这种具象概念更容易照做。

### 18.4 修法三：合并后把蒙版补回来
上一轮把元素层重建改成「剪贴 + 合并」后，`mergeLayers` 会把蒙版烘焙进像素 →
用户拿到的是一张没有蒙版的像素层（可编辑性下降，看起来像"蒙版丢了"）。
新增 `restoreMaskFromAlpha(doc, layerId)`：合并后按结果层透明度重建一个图层蒙版
（只 `selectLayerTransparency` + 建蒙版，**不羽化**），失败只记日志、层照常可用。

## 20. 实机反馈三项修复（2026-11-02 午）

### 20.1 相似图在上一次结果上继续改
**现象**：连跑两次相似图，第二次像在第一次的输出上微调，而不是按当前画面重新生成。

**日志**（04:52 / 04:54 两次 `inst=similar`）：
```
导出主源图像 1024×1024 ...
export: doc dup -> id=215 1024x1024
数据大小两次完全一致（2787134B）
```
两次导出的 dataURI 字节数一模一样 —— 主源画面没变，但**画面里已经混进了上一次的结果层**
（更早那次局部重绘插入的「AI 局部重绘 · 白猫」）。`t.layerIds` 只挡「入队之后新增的层」，
挡不住「入队前就存在的上次结果」：它被当成用户原始画面的一部分合并导出了。

**修法**：区分「用户资产」与「插件产出」。
- `ps.js` 新增 `PLUGIN_RESULT_IDS` + `markPluginResultLayer()`：每次 `placeEntryAsLayer` 落层后登记 id；
  `prunePluginResultLayers(doc)` 在导出前剔除已被删除的 id（跨会话不保留，重开 PS 后算用户资产）。
- `hideLayersNotIn(doc, keepIds, hideIds)` 扩展成三重语义：
  1. 不在 `keepIds` 里的（并发任务后写入的）→ 隐藏；
  2. 在 `hideIds` 里的（插件上次结果）→ 隐藏；
  3. **当前选中的图层永远保留** —— 用户选它就是要以它为源（想在上次结果上迭代时，选中它即可）。
- `withSourceSnapshot()`、扩图参考图导出、拆图原图导出三处全部接上 `sourcePollutionIds(doc)`。
- 日志改成 `export: 临时隐藏输入污染层 N 个（上次结果 / 并发新层）`，下次复验一眼能看出来。

### 20.2 历史「插入为新图层」不置灰、无提示
**原因**：UXP 对 `<button disabled>` 的 `:disabled` 伪类重绘不稳定，`title` 属性也不弹原生 tooltip。
用户看到的是「按钮能点但点了没反应」+「没有任何说明」。

**修法**：
- 状态用 class：`.hj-actions button.is-dis`（虚线边 + opacity .45），不再只依赖伪类；
- 说明用自绘浮层 `.hj-tip`（绝对定位在卡片内，`mouseover/mouseenter` 显示，`mouseout` 隐藏），
  比系统 tooltip 可控，也不受 UXP 覆盖层穿透影响；
- 按钮文字直接说原因：运行中显示「运行中…」，无图显示「无可插入图」——
  即使浮层失效，用户也能看懂；
- `setRunning()` 在历史页且运行状态变化时立即重渲染（开跑变灰、跑完解禁，不用切页）。

### 20.3 提示词框粘不进去

  `insertIntoTextarea()`（有光标插光标处，否则追加）、`attachPasteTools()`；
- 提示词卡片工具行加「📋 粘贴」按钮，显式从剪贴板取文本；
- `Cmd/Ctrl+V` 兜底：按键后 180ms 检查文本是否变化，没变就自己读剪贴板补上，

## 21. 实机反馈第二批（2026-11-02 晚）

### 21.1 后台有任务时，历史结果插不进去
**原因**：历史卡片的「插入为新图层」按全局 `running` 禁用，`historyReinsert()` 开头也 `if (running) return`。
可 `running` 只代表"有生成任务在跑"，跟"能不能往画布写一层"没关系 —— 用户以为按钮坏了。

**修法**：
- 按钮不再因 `running` 禁用，只保留「无可插入图 / 检查中」两种禁用态；
  运行中的说明文案改成「有新任务在跑，插入会在其落图之后执行」。
- `historyReinsert()` 去掉 `if (running) return`，并把 `executeAsModal` 换成
  `execModal(..., 3)`（带退避重试），真撞上模态作用域时自动等一拍。

### 21.2 无选区跑局部重绘直接失败
`local_redraw` 的 `selection` 是 `required`，无选区时在入口就被拒绝。用户的实际诉求是
「没框选就先整张改一版」。

**修法**：注册表给 `local_redraw` 加 `noSelArea: "canvas"`；`runCurrentInstance` 在
`selection === "required" && !sel` 时，若声明了 `noSelArea:"canvas"` 就记一条
「未框选区域：按整幅画面重绘」继续跑，否则维持原来的报错。
链路本身对 `sel = null` 是安全的（`useMask/useClip/localWhole` 全部为 false，
`computeExportBounds(null)` 返回全画布，走 i2i 无蒙版）。

### 21.3 扩图挖空蒙版：默认关 + 单边扩展的空白条
- `punchRect`（把原图矩形从结果层挖空）默认关闭。模型整体重绘的融合更自然；
  挖空在「只扩单边」时容易与原图错位、露出空白条（F2-21 的现场）。
- 设置 ▸ 默认参数新增「扩图保留原图区域（挖空蒙版；默认关）」，键
  `grsai.outpaint.keepOriginal`，需要原区域像素绝对不变时再打开。
- 落图仍 `stretch` 铺满整块扩展后画布，四边不留白。

### 21.4 改过画布比例后抠图被拉变形
`placeResultAsLayer` 的 `stretch` 是「宽高各自缩放」，模型返回比例与目标区域不一致时必然变形
（画布从 1:1 改成 16:9 后尤其明显）。

**修法**：新增 `fitCoverSize()`（等比 cover）与 `opts.fitCover`：
- 比例差 ≤ 1% → 仍走 `stretch`（编辑类 1:1 回贴行为不变）；
- 比例差 > 1% → 等比放大到铺满，再用矩形选区建图层蒙版把溢出部分裁掉
  （`selectRect(target)` → `applySelectionAsLayerMask`，reveal 内部、隐藏外部）。
结果：**不变形、也不留空白**，蒙版可再编辑。编辑类落层统一传 `fitCover: true`；
拆图与扩图不传（它们靠请求档位保证比例）。

## 22. 无选区局部重绘：闸门才是真正的拦路点（2026-11-02 晚补）

### 22.1 上一轮修错了地方
上一轮只在 `runCurrentInstance` 的入口加了 `noSelArea:"canvas"` 分支，但**运行按钮本身是灰的** ——
`ui.js` 的 `evalRunGate()` 里还有一道 `inst.selection === "required" && !sel → ok:false`。
闸门不过，按钮禁用，用户连点都点不动，入口那行代码永远走不到。

### 22.2 改法
- `evalRunGate()`：声明 `noSelArea:"canvas"` 的功能不再锁按钮，

### 23.2 两个编码坑（都是踩过才知道）
1. **压缩包内文件名一律 ASCII**。macOS 的 `zip` 不写 UTF-8 通用标志位，
   `安装说明.txt` 这种名字在 Windows 资源管理器里会变成 `�?�?说�??.txt`（旧包就是这个下场）。
   现在顶层全部用 `INSTALL-Windows.txt` / `Install-Windows.bat` 这种 ASCII 名。
2. **.txt 带 BOM，.bat 不带 BOM**。老记事本靠 BOM 认 UTF-8；而 cmd 会把 BOM 当成命令的一部分，
   报 `'∩╗┐@echo' 不是内部或外部命令`。所以 bat 用纯 UTF-8 + 开头 `chcp 65001`。

`.bat` 里还加了一条实际最容易失败的检查：`tasklist | find "Photoshop.exe"`，
PS 开着时先警告——文件被占用时装进去也不生效，用户只会看到「功能不对」而不是「没装上」。

## 24. 本地 ComfyUI：换机器后模型对不上（2026-11-02 深夜）

### 24.1 先确认打包没问题
用户问「ComfyUI 那一块是不是没写进包」。查了：内置模板、节点角色、执行链路全在
`js/services.js` / `js/api.js` 里（模板是 JS 字符串常量，不是外部 JSON），
`build.mjs` 的 `ENTRIES = index.html / manifest.json / js / icons` 已覆盖，
包里 `services.js` 命中 7 处 ComfyUI 关键字，`index.html` 挂载与按钮绑定齐全 —— **不是打包漏了**。

### 24.2 真正的问题：模板里写死的是作者的模型文件名
`COMFY_TEMPLATES` 三条工作流写死：
```
unet_name: flux-2-klein-4b-Q8_0.gguf
clip_name: Qwen3-4B-UD-Q6_K_XL.gguf
vae_name : flux2-vae.safetensors
```
换到 Windows 上，只要出现下面任一差异就跑不起来，而旧版只在「检测全部」里干巴巴报「缺 xxx」：
1. 模型放在子目录里，且分隔符是反斜杠：`Klein\flux-2-klein-4b-Q4_K_M.gguf`；
2. 量化档不同：Q4_K_M / Q6_K / Q8_0；
3. 本机根本没装 ComfyUI-GGUF，没有 `UnetLoaderGGUF` / `CLIPLoaderGGUF` 节点。

### 24.3 加「适配本机模型」
**纯函数（services.js）**
- `comfyNormModelPath` / `comfyModelBase` / `comfyModelStem` / `comfyModelQuant`：
  归一分隔符、目录、扩展名、量化后缀；
- `comfyModelMatch(wanted, installed)`：原样 → 忽略分隔符大小写 → 同名文件 →
  同底模换量化（优先同量化）→ 唯一前缀命中；**两个候选说不清就返回空**，绝不硬套；
- `comfyAdaptWorkflow(workflow, probe)`：
  - 节点本机没有且可换（GGUF → `UNETLoader` / `CLIPLoader`）就换，并按目标节点的
    `object_info.required` 补默认参数（如 `weight_dtype`），已有参数不覆盖；
  - 文件按 `comfyModelMatch` 改写；
  - 返回 `changes`（改了哪个节点）与 `missingClasses` / `missingFiles`（改不动的如实报）。
- `comfyWorkflowModelSig` 归一后再排序：同一个模型写成 `Klein\x.gguf` 和 `Klein/x.gguf`
  不再被拆成两个下拉项。

**网络层（app.js）**
- `comfyClassInfo(base, cls)` 按「机器+节点」缓存 `object_info`（120s）；
- `comfyMakeProbe()` 一次性预取工作流用到的节点（含可能要换过去的标准加载器），
  给出同步 `has/required/list`，让纯函数保持可测；
- `comfyAdaptStore(force)`：逐预设找在线机器 → 适配 → 落盘，返回
  `adapted / unchanged / offline / missing / extra`；
- 三个入口：设置里新增「**适配本机模型**」按钮；「添加内置模板」后**自动**适配一次；
  「检测全部」改用 `comfyCheckPreset`，能分别报「缺模型文件 / 缺节点」。

### 24.4 报错要能指导动作
状态行一次说清三件事，例如：
```
已适配 3 个预设：Klein 4B 文生图（flux-2-klein-4b-Q8_0.gguf→Klein/flux-2-klein-4b-Q4_K_M.gguf）；…
缺模型文件：sdxl-base.safetensors（本机有 flux-2-klein-4b-Q4_K_M.gguf / qwen-image-Q4_K_M.gguf）
本机另有 2 个模型没配工作流：qwen-image-Q4_K_M.gguf、sdxl-base.safetensors（需要各自的 API 工作流）
```
两个设计取舍：
- 「缺节点」和「缺文件」可以同时存在，**不因为缺节点就放弃文件对齐**（早期版本会整条放弃，
  用户以为「无需改动」）；
- 机器在线但工作流的节点一个都不存在时，报「缺节点」而不是「离线」——两回事。

## 25. 通用 Checkpoint 模板 + 运行期模型校准（2026-11-02 深夜）

### 25.1 用户的实际诉求
「本地模型是不是必须导入自己的工作流？」——是，但颗粒度是「每套计算图」。
问题在于：换成 SDXL / SD1.5 / Pony 这类单文件 checkpoint，就得自己从 ComfyUI 导一次 API 工作流，
再点一次「适配本机模型」，换台机器又要重来。

### 25.2 新增第 4 条内置模板：通用 Checkpoint 文生图
```
CheckpointLoaderSimple(ckpt_name: "") → CLIPTextEncode ×2(PROMPT/NEGATIVE)
→ EmptyLatentImage(SIZE) → KSampler → VAEDecode → SaveImage(OUTPUT)
```
`ckpt_name` **故意留空**：适配时由 `comfyAdaptWorkflow` 挑本机第一个可用 ckpt
（`changes[0].kind === "auto"`，状态行显示「自动选中 xxx」）。默认 20 步 / CFG 7，
Turbo/Lightning 这类模型自己调步数即可。

### 25.3 运行期校准：换机器不用再点「适配」
`api.js` 新增 `comfyRunFixModels(wf, base)`，在 `callComfyUI` 拿到 `base` 之后、提交之前跑：
- 按 `object_info` 取本机该加载器的可选列表（`base|Class|field` 缓存 5 分钟）；
- 配置里的名字**在本机存在** → 原样不动（避免误换模型）；
- 不存在或为空 → 换成列表第一个，并写日志 `comfy run: 本机没有「x」，改用「y」`；
- 任何异常都吞掉，绝不影响正常提交；查不到列表（老版本/离线）就完全不动。

于是三种情况都不再需要手动适配：
1. 通用模板第一次用（ckpt 留空 → 自动挑）；
2. 同一预设换机器（名字不在 → 自动换）；
3. 同一个模型换了量化档（`comfyModelMatch` 同底模匹配）。

运行期替换缺失模型、运行期保留已有模型（不乱换）。全量 **705 项通过**。
